## 3.2 Атрибуты качества

Это нефункциональные требования, определяющие надежность и удобство системы.

1.  **Доступность:** система должна быть доступна 97% времени (SLA), исключая запланированные технические работы.
2.  **Производительность:** 
    *   Время отклика API на основные операции не должно превышать 300 мс.
    *   Время генерации AI-инсайта не должно блокировать основной интерфейс.
3.  **Масштабируемость:** архитектура должна поддерживать до 10 000 активных пользователей без деградации производительности БД.
4.  **Безопасность:** 
    *   Все персональные данные (email, Telegram ID) должны храниться в зашифрованном виде.
    *   Обмен данными со всеми внешними системами должен происходить строго по протоколу HTTPS.
5.  **Удобство использования:** интерфейс должен быть адаптирован для мобильных устройств (Mobile-first web app), так как основной сценарий ввода данных — "на ходу".

## 3.3 Ограничения

Технические и бизнес-рамки, в которых ведется разработка.

1.  **Технологический стек:** 
    *   СУБД: PostgreSQL.
    *   AI-движок: локальный инстанс Ollama (модель Qwen 2.5) для минимизации затрат на API и обеспечения приватности.
2.  **Инфраструктура:** система должна разворачиваться в Docker-контейнерах для обеспечения переносимости.
3.  **Локализация:** на первом этапе интерфейс и AI-инсайты предоставляются только на русском языке.
4.  **Правовые ограничения:** соответствие 152-ФЗ "О персональных данных".
5.  **Бюджет:** использование бесплатных open-source библиотек и локальных моделей для минимизации операционных расходов на старте.
