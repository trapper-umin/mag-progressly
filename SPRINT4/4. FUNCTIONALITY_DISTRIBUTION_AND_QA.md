## 4. Распределение функциональности по модулям и качественные характеристики

В данном разделе представлена модульная декомпозиция системы Progressly. Мы распределяем 10 ключевых функциональных модулей по техническим компонентам архитектуры и определяем требования к их качеству.

### 4.1 Распределение модулей по компонентам (Functional Mapping)

Для обеспечения высокой отказоустойчивости и производительности модули распределены между синхронным ядром (API) и асинхронным обработчиком (Worker):

| Модуль | Описание ответственности | Размещение (Контейнер) |
| :--- | :--- | :--- |
| **admin** | управление тарифами, лимитами и просмотр агрегированной аналитики по пользователям (bz1, bz6). | api backend / web app |
| **auth** | реализация беспарольного входа через email (magic link) и интеграция с telegram oauth (fr-01, fr-02). | api backend |
| **ai** | подготовка контекста из данных пользователя, взаимодействие с локальной моделью ollama и выдача инсайтов. | background worker |
| **goals** | создание целей, визуализация прогресса и автоматический расчет «серий» (streaks) (fr-09, fr-10). | background worker / api |
| **notifications** | планирование и отправка push-напоминаний через telegram bot api согласно расписанию (fr-15). | background worker |
| **payments** | интеграция с yookassa, обработка первичных платежей и логика ежемесячных автосписаний (fr-18). | api backend / worker |
| **security** | шифрование персональных данных, контроль доступа (acl) и ограничение частоты запросов (rate limiting). | api backend |
| **support** | сбор обратной связи и привязка обращений пользователей к логам их активности (br-fb-3). | api backend / web app |
| **tracker** | конструктор настраиваемых полей (логика, числа) и интерфейс ежедневного календаря (fr-05, fr-07). | api backend / web app |
| **users** | управление профилями, настройками часовых поясов и процедура удаления аккаунта (fr-03, fr-04). | api backend |

### 4.2 Качественные характеристики (Quality Attributes)

Распределение модулей позволяет нам задать конкретные стандарты качества для всей системы:

1.  **Доступность (Availability):**
    *   Целевой показатель: 97%.
    *   Реализация: модули **tracker** и **auth** имеют наивысший приоритет. сбой в модулях **ai** или **support** не должен блокировать работу основных функций приложения.

2.  **Производительность (Performance):**
    *   Целевой показатель: время отклика для модуля **tracker** < 300 мс (p95).
    *   Реализация: «тяжелые» вычисления модулей **ai** и **goals** (массовый пересчет серий) вынесены в фоновые процессы, чтобы не замедлять работу интерфейса.

3.  **Безопасность (Security):**
    *   Стандарт: соответствие 152-ФЗ.
    *   Реализация: модуль **security** изолирует доступ к базе данных на уровне строк (row-level security), гарантируя, что пользователь видит только свои данные. все ключи внешних систем (yookassa, telegram) скрыты в переменных окружения.

4.  **Масштабируемость (Scalability):**
    *   Стандарт: поддержка роста до 10 000 активных пользователей.
    *   Реализация: модули **notifications** и **ai** спроектированы так, чтобы их можно было распределять на несколько серверов параллельно при росте нагрузки.

### 4.3 Ограничения и технологические зависимости

*   **Инфраструктура:** все модули упакованы в docker-контейнеры. это упрощает развертывание и обеспечивает идентичность среды разработки и продакшена.
*   **Взаимозависимость:** модуль **payments** является критическим узлом: при его недоступности новые пользователи не смогут активировать pro-функции, однако модули **tracker** и **goals** должны продолжать работу в режиме free-тарифа.
*   **Ии-ресурсы:** работа модуля **ai** жестко ограничена вычислительной мощностью локального сервера ollama. для предотвращения перегрузки вводится очередь задач, где приоритет отдается пользователям с pro-подпиской.
