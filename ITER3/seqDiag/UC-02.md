# Вариант использования UC-02 Получать AI-сводки

## Краткое описание
Пользователь запрашивает персональную аналитическую сводку по своим привычкам за выбранный период. Система проверяет права доступа (Pro-тариф), агрегирует накопленные записи трекера и цели, формирует контекст и отправляет запрос в локальную модель Ollama AI. Полученные выводы, инсайты и советы сохраняются в системе и отображаются пользователю с возможностью отметки о прочтении.

## Действующие лица
*   Основное: пользователь (требуется Pro-тариф)
*   Второстепенное: Ollama AI (внешняя система генерации текста)

## Предусловия
1. Пользователь авторизован в системе.
2. У пользователя настроен хотя бы один активный трекер.
3. У пользователя активен тариф PRO (или действует триал-период).

## Постусловия
*   Успешное завершение: в системе создана и сохранена запись AISummary с аналитикой за запрошенный период (текст сводки, массив инсайтов, рекомендации, статус «не прочитано»). Пользователю отображен структурированный отчет.
*   Неуспешное завершение (ошибка AI / сети): запись сводки не создается, пользователю выводится информативное сообщение о временной недоступности сервиса с предложением повторить попытку позже. Пользовательские данные не повреждены.
*   Неуспешное завершение (недостаточно данных): сводка не генерируется, система предлагает пользователю продолжить заполнение трекера до накопления минимального объема данных.

---

## Основной поток событий
1. Сценарий начинается, когда Пользователь открывает раздел «AI-аналитика» (или переходит по системному уведомлению о готовности сводки).
2. Система проверяет активность сессии пользователя.
3. Система проверяет статус подписки пользователя на соответствие тарифу PRO.
4. Система проверяет наличие ранее сгенерированной сводки за запрашиваемый период.
5. Система находит активные трекеры пользователя и извлекает журнал записей за последние 7 дней.
6. Система находит цели пользователя, связанные с данными трекерами, и рассчитывает текущий процент их достижения.
7. Система проверяет полноту извлеченных данных (достаточность для качественного анализа).
8. Система агрегирует данные в единый JSON-контекст и формирует промпт для нейросети.
9. Система отправляет запрос во внешний сервис Ollama AI.
10. Ollama AI анализирует динамику, выявляет аномалии (спады, лучшие дни) и возвращает структурированный ответ.
11. Система валидирует полученный ответ и сохраняет новую сущность сводки в базу данных.
12. Система отображает сгенерированную сводку, инсайты и персональные советы в интерфейсе пользователя.
13. Пользователь знакомится с отчетом и нажимает кнопку «Ознакомлен».
14. Система обновляет статус сводки на «прочитано».

---

## Альтернативные потоки

### 2А. Сессия истекла
1. Система обнаруживает, что токен доступа недействителен.
2. Система перенаправляет пользователя на страницу входа.
3. Пользователь выполняет авторизацию.
4. Система возвращает пользователя в раздел «AI-аналитика».
5. Происходит возврат к шагу 2 основного потока.

### 3А. Отсутствует подписка PRO (пользователь тарифа FREE)
1. Система обнаруживает, что у пользователя активен бесплатный тариф.
2. Система блокирует вызов модуля аналитики.
3. Система отображает демонстрационный экран с описанием преимуществ AI-аналитики и кнопкой перехода на Pro.
4. Выполняется переход к варианту использования «Оформить подписку».
5. Сценарий завершается.

### 4А. Сводка за выбранный период уже существует (кэш)
1. Система обнаруживает в базе данных готовую запись AISummary за указанный период.
2. Система пропускает этапы сбора данных и обращения к нейросети (шаги 5–11).
3. Происходит переход к шагу 12 основного потока (мгновенное отображение из базы).

### 7А. Недостаточно данных для анализа
1. Система обнаруживает, что за анализируемый период пользователь внес менее 3 записей в трекер.
2. Система прерывает процесс генерации.
3. Система выводит сообщение: *«Недостаточно данных для построения аналитики. Заполните трекер минимум за 3 дня, чтобы AI смог найти закономерности»*.
4. Сценарий завершается.

### 9А. Временная недоступность Ollama AI (таймаут или ошибка сервиса)
1. Система фиксирует сетевую ошибку или отсутствие ответа от сервиса Ollama в течение заданного таймаута (15 секунд).
2. Система выполняет повторные попытки запроса (до 3 раз с экспоненциальной задержкой).
3. Если сервис не отвечает:
   1. Система логирует ошибку интеграции.
   2. Система выводит пользователю уведомление: *«Сервис аналитики временно перегружен. Мы уже решаем проблему. Попробуйте обновить страницу через несколько минут»*.
4. Сценарий завершается без создания некорректных записей.

### 10А. Невалидный формат ответа от нейросети
1. Система получает ответ от Ollama, но структура JSON повреждена или не соответствует ожидаемой схеме.
2. Система фиксирует ошибку парсинга.
3. Выполняется переход к шагу 9А (повторная попытка генерации с очищенным контекстом).

### 13А. Пользователь закрыл страницу без отметки о прочтении
1. Пользователь покидает раздел аналитики, не нажав «Ознакомлен».
2. Статус сводки в базе данных остается UNREAD.
3. В главном меню сохраняется бейдж-индикатор о наличии непрочитанного отчета.
4. Сценарий завершается.
