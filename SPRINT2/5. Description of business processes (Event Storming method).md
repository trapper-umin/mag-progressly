Для формализации функциональных требований и логики работы системы была применена техника **Event Storming**. Это позволило выявить ключевые события предметной области, действия пользователей и правила автоматизации.

#### Легенда модели:
*   **Событие (Domain Event):** Факт, который уже произошел в системе (в прошедшем времени).
*   **Команда (Command):** Намерение пользователя или системы произвести действие.
*   **Актор (Actor):** Кто именно инициирует действие.
*   **Внешняя система (External System):** Сторонний сервис, участвующий в процессе.
*   **Политика (Policy):** Реактивное правило («Если произошло событие А, то выполнить команду Б»).

#### Поток 1: Регистрация и персонализация трекера
*Цель: Быстрый старт и настройка персональной таблицы под нужды пользователя.*

1.  **[Актор: Пользователь]** → **(Команда: Запросить вход)**.
2.  **[Внешняя система: SMTP / Telegram]** → **(Событие: Ссылка для входа отправлена)**.
3.  **(Событие: Аккаунт подтвержден)**.
4.  **[Политика]:** Если аккаунт создан впервые → **(Команда: Создать пустой трекер)**.
5.  **[Актор: Пользователь]** → **(Команда: Добавить поле «Спорт», тип: boolean)**.
6.  **(Событие: Структура трекера изменена)**.
7.  **[Актор: Пользователь]** → **(Команда: Установить цель «15 тренировок»)**.
8.  **(Событие: Цель установлена)**.

#### Поток 2: Ежедневный цикл трекинга и мотивации
*Цель: Обеспечение регулярности ввода данных и визуализация прогресса.*

1.  **[Политика]:** Наступило время напоминания (согласно часовому поясу пользователя).
2.  **[Внешняя система: Telegram Bot API]** → **(Команда: Отправить пуш-уведомление)**.
3.  **(Событие: Напоминание доставлено)**.
4.  **[Актор: Пользователь]** → **(Команда: Внести значение «Да» за текущую дату)**.
5.  **(Событие: Значение сохранено)**.
6.  **[Политика]:** Если значение внесено → **(Команда: Пересчитать Streak/Серию)**.
7.  **(Событие: Серия продлена)**.
8.  **(Событие: Прогресс по цели обновлен)**.

#### Поток 3: Генерация AI-инсайтов (Аналитический цикл)
*Цель: Превращение накопленных данных в интерпретируемые советы и выводы.*

1.  **[Политика]:** Наступило время формирования периодического отчета (например, утро понедельника).
2.  **(Команда: Собрать данные за неделю)**.
3.  **(Событие: Выборка данных сформирована)**.
4.  **[Внешняя система: Ollama AI]** → **(Команда: Сгенерировать сводку и инсайты)**.
5.  **(Событие: AI-ответ получен)**.
6.  **(Событие: Инсайт опубликован в ленте пользователя)**.
7.  **[Актор: Пользователь]** → **(Команда: Прочитать отчет)**.
8.  **(Событие: Инсайт помечен как прочитанный)**.

#### Поток 4: Монетизация и управление Pro-функциями
*Цель: Обеспечение жизненного цикла платных услуг.*

1.  **[Актор: Пользователь]** → **(Команда: Выбрать Pro-тариф)**.
2.  **[Внешняя система: YooKassa]** → **(Команда: Создать платежную сессию)**.
3.  **(Событие: Платеж инициирован)**.
4.  **[Внешняя система: YooKassa]** → **(Событие: Оплата успешно проведена)**.
5.  **[Политика]:** При получении Webhook подтверждения об оплате → **(Команда: Активировать Pro-статус)**.
6.  **(Событие: Лимиты пользователя расширены)**.
7.  **[Политика]:** По истечении расчетного периода (30 дней) → **(Команда: Создать запрос на автосписание)**.

#### Ключевые агрегаты предметной области
На основе анализа событий были выделены основные бизнес-агрегаты (группы объектов), которые лягут в основу проектирования базы данных:

*   **User Aggregate:** Управление профилем, авторизационными данными и текущим статусом подписки.
*   **Tracker Aggregate:** Конфигурация структуры полей (метаданные таблицы: названия, типы данных, периодичность).
*   **Entry Aggregate:** Фактические логи данных (значения, привязанные к конкретному пользователю, полю и дате).
*   **Goal Aggregate:** Описание целевых показателей пользователя, текущий процент выполнения и связь с полями трекера.
*   **Billing Aggregate:** История транзакций, идентификаторы способов оплаты для рекуррентных списаний и история подписок.
